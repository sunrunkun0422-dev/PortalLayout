# 技术对比分析：SALVe 与开口引导的多房间布局估计

核查日期：2026-10-26。用途：硕士开题预演。本文区分论文事实、代码事实、已有实验与拟验证假设；本轮没有执行模型实验。先打开 [四图预览](index.html)，汇报主图为 [我的论文完整技术路线](我的论文_完整技术路线.svg)。

## 1. 先修正核心说法

**“SALVe 只使用开口几何，而我使用更多视觉特征”不成立。** SALVe 的几何候选生成之后有明确的视觉对齐验证。应比较“证据用于判断什么、在什么阶段使用”，而不是“是否使用视觉”。[SALVe，§4.2–4.3](https://www.ecva.net/papers/eccv_2022/papers_ECCV/papers/136910632.pdf)

推荐表述：

> 本课题以开口实例作为跨房间关联单元，联合结构代理、邻域视觉上下文和几何属性，并针对具体候选对双向检索证据，学习对应关系与无匹配判断。在此基础上，拟研究可靠跨图观测对局部墙段及开口端点的约束。研究一已有实现与初步实验，研究二尚待实施；两者是否改善可靠重建，需要受控实验验证。

“更多特征”可以描述实现细节，不能作为贡献结论；上下文中的家具、纹理也可能导致误匹配，作用必须通过消融验证。

## 2. SALVe 的流程与边界

[图 1](SALVe_技术路线.svg)依据原论文 Fig. 2、Fig. 3 和 §4，而非本项目的历史 Matcher。下表对应原论文阶段，官方代码固定到提交 `7bb3e78d79892f805d3662f1f86f080da47918a1`。

| 阶段 | 输入 → 输出；处理目的 | 主要证据 |
|---|---|---|
| 单图预测 | 全景 → 布局、置信度、W/D/O；深度另供渲染 | 论文 §4.1–4.3；[官方运行流程](https://github.com/zillow/salve#running-reconstruction) |
| 几何提案 | 同类 W/D/O → 相对对齐假设；用方向、中心和宽度约束缩小候选 | §4.2；[align_rooms_by_wd](https://github.com/zillow/salve/blob/7bb3e78d79892f805d3662f1f86f080da47918a1/salve/utils/wdo_alignment.py#L107) |
| 外观验证 | 相对假设与深度渲染纹理 → 对齐评分；判断假设是否可信 | §4.3 / Fig. 3：两图地板和天花板共四幅 RGB 视图，ResNet 验证 |
| 全局定位 | 接受的相对约束 → 全景全局位姿 | §4.4；[planar_slam](https://github.com/zillow/salve/blob/7bb3e78d79892f805d3662f1f86f080da47918a1/salve/algorithms/pose2_slam.py#L57) |
| 房间恢复 | 已定位局部轮廓 → 同房间分组与置信度融合 → 平面图 | §4.5；[refine_shape_group_start_with](https://github.com/zillow/salve/blob/7bb3e78d79892f805d3662f1f86f080da47918a1/salve/stitching/shape.py#L167) |

SALVe 的方法假定全景直立、相机高度已知，在同层平面运动条件下使用 SE(2) 位姿。其代码出现 `Sim2` 容器不意味着论文把开口宽度比当作自由尺度估计。本项目采用相机高度归一化坐标与 Sim(2) 多假设，最新单位尺度设置是实验先验。[论文 §4.1–4.2](https://www.ecva.net/papers/eccv_2022/papers_ECCV/papers/136910632.pdf)、[官方位姿输出的单位尺度](https://github.com/zillow/salve/blob/7bb3e78d79892f805d3662f1f86f080da47918a1/salve/algorithms/pose2_slam.py#L284)

**SALVe 有房间轮廓修整。** 因此不能说它“只移动房间、从不改变形状”；本课题研究二应限定为“以可靠跨房间对应及有效观测为条件，显式更新局部墙段和开口参数”，区别于已有同房间置信度轮廓融合。[官方轮廓融合实现](https://github.com/zillow/salve/blob/7bb3e78d79892f805d3662f1f86f080da47918a1/salve/stitching/shape.py#L266)

## 3. 当前项目实际上有什么

完整源码索引见 [代码证据清单](代码证据清单.md)，图中 C01–C13 与该表对应。

| 模块 | 当前事实 | 不能由此推导的结论 |
|---|---|---|
| 单图前端 | Bi-Layout 双布局与 Opening Head，保存真实二维特征和稳定候选 ID | 前端不是本课题从零提出；开口不是语义 W/D/O 三分类的等价复现 |
| 单图开口增强 | 1D 基础池化、20 点结构代理、软覆盖上下文、12 属性及 mask、门控融合、图内注意力 | 没有精确门顶检测；没有显式分割“门后共同可见空间” |
| 双图 Matcher | 源和目标候选共同生成查询；双向检索二维记忆；对称打分；Sinkhorn 和 dustbin | attention 不是经监督验证的稠密像素对应；分数不是校准成功证明 |
| 位姿候选 | 端点翻转多解；独立几何覆盖；尺度收缩实验；保留来源及去重 | `local_m2` 不会更新原房间多边形，不等于研究二 |
| 假设验证 | 7 通道几何 BEV、池化视觉与描述子、几何及有效性特征；对称 CNN+MLP 已训练 | 不是 RGB BEV 重投影；非拟合证据“存在”不等于证据“支持”该位姿 |
| 整层后端 | 全部无序图像对；森林、鲁棒 Sim(2) PGO；孤立节点、分量、结构图和独立七指标 | PGO 不修正局部形状；接口完成不代表可靠整层重建已完成 |
| 房间融合 | 完整链接与区域并集已有；学习同空间分类器有实现 | 最新实验关闭融合，room 未训练，不宣称 complete-room 已恢复 |

图 2 展示当前可运行分支；图 3 展示最终研究架构。两张图不能互相替代。最新已有实验为 [2026-10-26 几何与验证器报告](../../experiments/research1_pose_geometry_20261026_0245/final_report.md)：

- 固定 selection 跨房 R3 检索集合 **711 对**，含合格位姿候选由 **30 对增至 81 对**。这是候选可解上限，不能称为正确接边数量。
- 固定弱对应集合 **203 对**，合格候选 **47→182**，依赖已知弱对应，不能作为纯预测结果。
- V0/V1 均训练完成，但预设工作点均不可行；过滤结果不接边，排序结果仅作诊断。
- 20 个开发楼层的排序结果中，面积 IoU 与部分平移指标改善，但定位覆盖与结构指标并非同步改善。没有“系统整体优于 SALVe”的证据。
- `calibration` 是已使用过的开发验证数据，不是独立留出测试。

## 4. 五项实质区别与可验证假设

以下是本课题的机制分析，不是关于 SALVe 性能缺陷的已证实结论。

| 比较维度 | 本课题的区别 | 为什么可能有用 | 必须如何证明 |
|---|---|---|---|
| 关联判别单元 | 对具体开口实例建模并输出一对一／无匹配分配 | 重复开口不仅靠形状区分；候选间竞争可限制相互冲突的对应 | 固定候选和位姿求解器，比较高精确率工作点的跨房召回 |
| 视觉进入阶段 | 在建立开口对应时使用邻域上下文，并对候选对条件化检索 | 可在进入位姿验证前减少部分外观相似误配 | 基础池化、结构、上下文、几何、图内交互和条件化检索的消融 |
| 判别层次 | 开口对应与位姿正确性分为两级；匹配正确仍可能几何错误 | 可分别定位对应误差与几何误差 | 正确对应下的位姿上限、实际候选上限、最终选解对照；不能只看匹配 AP |
| 研究二的优化对象 | 拟显式修改局部墙段方向／位置及开口端点 | 错误端点会造成系统位姿偏差，仅移动整张布局未必能消除 | 固定位姿与对应的局部优化；检查共享区域改善和非共享区域退化 |
| 全层工程协议 | 保留所有输入与分量、独立评价、预测与 GT 隔离 | 使失败可诊断，避免强连导致虚假完整 | 全量公开断连、错边及七指标；这属于评估与工程严谨性，不单列算法创新 |

全对调度在本项目中仍然存在。不能从“每张图编码一次”推出整体复杂度低于 SALVe；必须分别计入候选对检索、渲染／验证、缓存与后端耗时，公平测量之后再讨论效率。

## 5. 创新边界：目前可以说到什么程度

**研究一可形成研究假设，但当前证据还不足以宣称有效创新。** 具体问题是：在低重叠、重复开口及 unknown 监督条件下，开口实例条件化证据检索能否提高固定误接受率下的跨房间对应召回。模型结构已实现，贡献须由公平对照与误差分解支撑。

**研究二具备独立问题，但当前是方案。** 初始位姿、观测有效性、误匹配抑制及局部形状可辨识性都需要解决。仅共享开口端点对齐不能唯一约束所有邻墙，更不能把两间不同房间的全部墙面强制重合。

需要排除的已有贡献：

- **Bi-Layout** 的双布局、上下文嵌入及利用双预测揭示歧义属于基础论文；开口增强和跨图匹配是在其输出上扩展。[CVPR 2024 论文页](https://openaccess.thecvf.com/content/CVPR2024/html/Tsai_No_More_Ambiguity_in_360deg_Room_Layout_via_Bi-Layout_Estimation_CVPR_2024_paper.html)、[作者项目页](https://liagm.github.io/Bi_Layout/)
- **CoVisPose** 已进行跨图 Transformer 交互、逐列共视／对应／边界预测，并支持位姿回归或几何求解。区别需要落到“开口实例候选对”及拒绝机制，而非泛化地声称首次利用视觉对应。[§3–4 / Fig. 2](https://www.ecva.net/papers/eccv_2022/papers_ECCV/papers/136920610.pdf)
- **GPR-Net** 已联合处理全景配准和布局，利用边界对应与共视，再将布局合并。这里仅根据作者摘要核对这一重叠范围；未据此断言它没有局部结构修正。研究二正式定稿前应进一步逐项核查全文。[作者预印本](https://arxiv.org/abs/2210.11419)
- 注意力、dustbin、Sinkhorn、CNN、PGO 和并集都是已有机制。合理组合可以是方法实现，但不能逐个包装为原创。

“具备硕士研究可展开性”是基于问题与实现的判断，不是学术新颖性证明。现阶段最稳妥的贡献标题为：**面向跨房间可靠关联的开口实例条件化视觉—几何匹配**，以及 **可靠跨图观测约束的局部布局几何修正**（拟研究）。
