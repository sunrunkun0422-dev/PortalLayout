## 09 · 物理特征值得验证，先作为带质量权重的辅助证据

- **核心结论：** 优先验证独立增益：固定候选与预算，对比“分数基线”与“分数 + 物理特征”。
- **版式：** 上：提出的候选验证流程；下：物理特征与风险表
- **高亮：** A0 score-only 731；A4 full 729；不是已证明的 BEV 增益
- **页面具体文字：**

  - Top-N 候选
  - 固定 N 与原始候选
  - 预测几何 + 质量标记
  - 候选假设变换之后评价
  - Verifier → Accept / Reject
  - 物理特征不直接充当真值
  - 现有 Phase A：score-only 731 / full 729（physical-compatible Top-1）；BEV CNN 尚未训练。

| 候选物理特征 | 用途 | 风险 / 控制 |
| --- | --- | --- |
| 相对开口尺度、邻域墙向 | 用未参与拟合的结构检验 | 预测尺度有误差；保留 missing / quality |
| 变换后房间重叠、墙面穿越 | 检查不合理空间冲突 | 开敞区域允许相连；避免硬阈值一刀切 |
| 多边 cycle consistency | 检验多房间位姿闭环 | 需真实闭环；重复走廊仍可能歧义 |

**讲述与证据边界：** 不能用求解时已被强制对齐的开口端点残差来证明匹配正确；应检查未参与拟合的邻域墙面和跨边一致性。同一房间不同视图可能高度重叠；重叠特征必须与“同空间/跨房间”关系类型联合解释。变换后法线关系不能使用未知 GT pose；预测单位不可靠时优先使用相对量。SALVe 提供候选对齐验证的相关研究方向，不证明本项目特征有效。
**来源：** T5 verifier 消融；SALVe [R1]；本页为待验证方案

## 10 · 开口类型可补充匹配特征，但应使用软标签而非硬筛选

- **版式：** 上：类型辅助分支；下：设计、消融、标签边界
- **高亮：** 当前是 openingness，尚无 door / opening 预测分类头；类别置信度与 unknown
- **页面具体文字：**

  - 候选视觉 / 上下文特征

  - 辅助类型估计
  - p(type) + uncertainty
  - 类型条件匹配
  - 软兼容性 / 特征门控

| 问题 | 建议设计 | 验证方式 |
| --- | --- | --- |
| 教师建议：不同开口采用不同特征 | 先以 door / opening 为标签起点 / 窗口可作结构参照，非直接房间通行边 | 类型混淆矩阵、可见性分层 |

| opening 标注未必对应物理门洞 | 核查 raw / complete 与虚拟分区语义 / “可通行性”需要独立标签审计 | GT-type oracle 仅作诊断上界 |

**讲述与证据边界：** 建议结合老师意见，但暂不为每类训练独立 Matcher：样本分布与误分类传递风险尚未量化。当前 OpeningSignalHead 的两个输出是 opening logit 和 depth scale，并非两个语义类别。ZInD 的 openings 也可能承担复杂空间分区作用 [R3]，不可直接等同于物理可通行门洞。
**来源：** 本地 Opening Head / pair mining；ZInD [R2]；待实现
